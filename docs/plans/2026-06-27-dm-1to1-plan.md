# DM 1-to-1 — Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking.
> **Branch:** `main` (o crear branch `dm-1to1` desde `main`)
> **Status:** Planning phase — Not started

**Goal:** Implement direct messaging (1-to-1) between users — backend (Prisma + NestJS) and frontend (Next.js). Includes sidebar user list, unified unread inbox at `/messages`, and real-time WebSocket delivery.

**Architecture:**
- New `Conversation` model in Prisma + `conversationId` optional field on `Message`
- Backend: New `conversations/` module with HTTP endpoints + WebSocket events
- Frontend: Sidebar gets "Usuarios" section (online/offline), `/messages` becomes unread-only inbox, DM UI reuses channel message components

**Tech Stack:** NestJS 11, Prisma 7.8, PostgreSQL, Socket.io, Next.js 16.2, Zustand, Tabler Icons, Framer Motion.

---

## Global Constraints

- All API responses wrapped in `{ success, data, message }` via `ResponseInterceptor`
- Auth via httpOnly cookie (`token`), JWT guard on protected endpoints
- WebSocket authenticates via cookie in `getUserFromSocket`
- Frontend typography: system classes from globals.css only (no Tailwind `text-*`)
- Frontend colors: theme classes only (no `text-white`/`text-black`)
- Tabler Icons for all icons, Framer Motion for animations
- "use client" only for interactive components
- Error responses sanitized (no stack traces, no internal details exposed)
- Connection pooling handled by Prisma adapter — no extra config needed

## Modelo de Datos (Prisma)

```prisma
model Conversation {
  id        String   @id @default(uuid())
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt      @map("updated_at")

  members   ConversationMember[]
  messages  Message[]

  @@map("conversations")
}

model ConversationMember {
  id             String       @id @default(uuid())
  joinedAt       DateTime     @default(now()) @map("joined_at")
  lastReadAt     DateTime?    @map("last_read_at")

  conversationId String       @map("conversation_id")
  conversation   Conversation @relation(fields: [conversationId], references: [id], onDelete: Cascade)

  userId         String       @map("user_id")
  user           User         @relation(fields: [userId], references: [id], onDelete: Cascade)

  @@unique([conversationId, userId])
  @@index([userId])
  @@map("conversation_members")
}
```

**CAMBIOS en modelo `Message`:**

```prisma
model Message {
  // ... campos existentes ...

  channelId      String?      @map("channel_id")       // ← ANTES: String (obligatorio)
  channel        Channel?     @relation(...)            // ← ANTES: obligatorio

  conversationId String?      @map("conversation_id")  // ← NUEVO: opcional
  conversation   Conversation? @relation(...)           // ← NUEVO: opcional

  // ... resto igual ...
}
```

Cada mensaje pertenece **O a un canal O a una conversación** (nunca ambos). Se valida en el use case.

## Backend — Endpoints

### HTTP

| Método | Ruta | Auth | Descripción |
|--------|------|------|-------------|
| `POST` | `/api/conversations` | ✅ | Obtener o crear DM con otro usuario. Body: `{ participantId: string }`. Si ya existe, devuelve la existente |
| `GET` | `/api/conversations` | ✅ | Listar conversaciones del usuario autenticado (con último mensaje y no leídos) |
| `GET` | `/api/conversations/:id/messages` | ✅ | Mensajes de una conversación (paginado, igual que channels) |
| `POST` | `/api/conversations/:id/messages` | ✅ | Enviar mensaje en DM |
| `PATCH` | `/api/conversations/:id/messages/:messageId` | ✅ | Editar mensaje (solo autor) |
| `DELETE` | `/api/conversations/:id/messages/:messageId` | ✅ | Eliminar mensaje (solo autor) |
| `PATCH` | `/api/conversations/:id/read` | ✅ | Marcar conversación como leída |

### WebSocket

| Evento | Dirección | Descripción |
|--------|-----------|-------------|
| `conversation.join` | Client → Server | Unirse a room `conversation:{id}` |
| `conversation.leave` | Client → Server | Salir de room |
| `conversation.message.send` | Client → Server | Enviar mensaje en DM |
| `conversation.message.sent` | Server → Client | Mensaje enviado (a los 2 participantes) |
| `conversation.message.edited` | Server → Client | Mensaje editado |
| `conversation.message.deleted` | Server → Client | Mensaje eliminado |

## Frontend — Componentes y Cambios

### Sidebar — Nueva sección "Usuarios"

- Debajo de "Administración" en el sidebar
- Lista de usuarios online/offline desde API
- Cada item: avatar (initiales) + nombre + dot verde/gris
- Click → navega a `/dm/[userId]`
- Sección colapsable como las demás

### `/messages` — Inbox de no leídos

- Muestra SOLO canales + DMs con mensajes sin leer
- Cada item: icono/avatar, nombre, preview del último mensaje, timestamp, badge con count
- Ordenados por más reciente primero
- **Empty state:** Cuando no hay nada sin leer → ilustración (IconMessageOff) + "No tienes mensajes pendientes"

### `/dm/[userId]` — Vista de DM

- Reutiliza `MessageList` y `ChatInput` de canales (mismos componentes)
- Header: avatar + nombre + online status
- WebSocket se conecta a `conversation:{id}`
- Si el usuario no existe → 404 custom

### Store (Zustand)

- `chat.store.ts` se extiende con:
  - `activeConversationId: string | null`
  - `conversations: Conversation[]`
  - `setActiveConversation(id)`
  - `addConversation(conv)`
